# Papyrus Admin UI

Vite + React 19 + TypeScript strict-mode scaffold for the Papyrus admin SPA.

## Local development

Install dependencies with `npm ci`, then run `npm run dev`. The API client uses
`/api/v1` and injects `X-Admin-Api-Key` and `X-Tenant-Id` from the browser store
(`dev-admin-key` / `main` defaults). The dev server proxies `/api/v1` to the
Admin API; it targets the injected Aspire service URL when one is present and
otherwise falls back to `http://localhost:5205`, which is the Admin API's
`launchSettings.json` port.

To serve the production bundle from `Papyrus.Api.Admin`, run `npm run build`.
The backend discovers the local `dist/` directory automatically; the admin
Dockerfile builds and publishes the same bundle to `wwwroot`, served at the
root path.

## Generated API client

`src/api/schema.d.ts` is generated by `openapi-typescript` from the **live**
Admin API document and is reviewable evidence: the `OpenAPI schema` workflow
regenerates it from a live capture on every push and pull request and fails on
drift, alongside the same check for `docs/api/openapi.json`.

Regenerate it while the Admin API is running:

```powershell
npm run generate-api
```

Do **not** generate it from `docs/api/openapi.json`. That artifact is stored
with sorted keys so its diff is stable, and generating from it yields a
semantically identical but differently ordered file that would fail the CI
comparison.
